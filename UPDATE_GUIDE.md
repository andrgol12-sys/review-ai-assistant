# Инструкция по обновлению Review AI Assistant

Этот документ описывает, как обновлять базу знаний, правила и тесты ассистента HomeTech.

## 1. Обновление базы знаний

Основная база находится в файле:

```text
data/knowledge_base_hometech.csv
```

В ней хранятся:

- типовые ситуации;
- тональность;
- темы;
- подтемы;
- характерные формулировки;
- шаблоны ответов;
- рекомендуемые действия;
- правила эскалации;
- уровни критичности;
- правила компании;
- примеры аналитики.

### Как добавить новую ситуацию

Добавьте новую строку с уникальным `id`.

Пример:

```csv
036,situation,complaint,negative,delivery,wrong_address,"привезли не по адресу; ошиблись адресом","Спасибо, что сообщили о проблеме с доставкой.","Проверить данные заказа и передать обращение сотруднику.",yes,high,"Не обещать повторную доставку без подтверждения.",""
```

После изменения CSV обязательно сохраните файл в кодировке UTF-8.

## 2. Добавление новой темы

Если появляется новая категория отзывов:

1. Добавьте её в CSV.
2. Добавьте тему в список допустимых тем в `prompts.py`.
3. Добавьте тему в структурированный классификатор в `assistant.py`.
4. При необходимости добавьте отдельное бизнес-правило в `_apply_business_rules()`.

Важно: названия тем должны совпадать во всех файлах.

## 3. Изменение правил компании

Правила компании хранятся в CSV в строках:

```text
record_type = company_rule
```

Например:

```text
delivery
return_exchange
warranty
compensation
privacy
```

Если правило изменилось, обновите соответствующую строку CSV.

Если правило критично для безопасности или эскалации, его также рекомендуется продублировать в Python-логике `_apply_business_rules()`.

## 4. Изменение системного промпта

Системный промпт находится в:

```text
prompts.py
```

После изменения промпта необходимо повторно запустить тесты.

Не рекомендуется менять сразу много правил одновременно. Лучше:

1. изменить один блок;
2. запустить тесты;
3. проверить результат;
4. только потом вносить следующие изменения.

## 5. Изменение бизнес-правил

Жёсткие правила критичности и эскалации находятся в:

```text
assistant.py
```

Метод:

```python
_apply_business_rules()
```

Именно Python-логика имеет приоритет для ключевых бизнес-правил.

Примеры:

```text
Опасная неисправность → high / escalation=True
Обычная неисправность → medium / escalation=True
Обычная задержка → medium / escalation=False
Компенсация → high / escalation=True
Возврат/обмен → medium / escalation=True
Юридическая угроза → high / escalation=True
```

Если добавляется новый обязательный сценарий эскалации, его нужно добавить в этот метод.

## 6. Обновление шаблонов ответов

Шаблоны находятся в колонке:

```text
response_template
```

файла:

```text
data/knowledge_base_hometech.csv
```

Шаблон должен:

- быть вежливым;
- учитывать ситуацию;
- не содержать ложных обещаний;
- не обещать компенсацию без решения сотрудника;
- не повторять лишние персональные данные;
- не утверждать, что действие уже выполнено.

## 7. Добавление нового теста

Тесты одиночных отзывов:

```text
tests/test_assistant.py
```

Групповая аналитика:

```text
tests/test_analytics.py
```

Новый тест рекомендуется добавлять, если:

- появилась новая тема;
- изменилось бизнес-правило;
- была найдена ошибка;
- добавлена новая критическая ситуация.

## 8. Проверка после обновления

После любых изменений обязательно выполнить:

```powershell
python tests\test_assistant.py
```

Ожидаемый результат:

```text
5/5 тестов пройдено
```

Затем:

```powershell
python tests\test_analytics.py
```

Ожидаемый результат:

```text
PASS
```

После этого можно дополнительно вручную запустить:

```powershell
python app.py
```

и проверить изменённый сценарий.

## 9. Адаптация под другую компанию или отрасль

Если ассистент адаптируется под другую компанию или направление бизнеса:

1. обновите название компании и описание в `prompts.py`;
2. замените или расширьте CSV-базу знаний;
3. обновите правила компании;
4. пересмотрите список тем отзывов;
5. добавьте новые тестовые сценарии;
6. повторно запустите все тесты.

## 10. Главное правило обновления

После любых изменений придерживайтесь последовательности:

```text
Изменение → тестирование → проверка → фиксация результата
```

Не рекомендуется считать обновление завершённым, пока автоматические тесты не проходят успешно.
